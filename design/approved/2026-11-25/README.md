## 必须保持的设计

### 账户页
- 暖白／浅灰／浅珊瑚红的设计语言，不再引入大面积绿色。
- 顶部用户信息卡、当前套餐卡、账户服务列表的既定结构与层次。
- 服务入口：我的钱包、订单记录、流量用量、工单支持、邀请好友、应用设置。
- 第三套底部导航的既定视觉风格、四个文字标签与安全区处理；二级页面须有返回操作。
- 禁止为了所谓“精修”随意重做卡片、替换配色、削弱文字对比度。

### 套餐页
- 保留已确定的标题和顶部「全部／周期性／一次性」筛选。
- 卡片标题在左；**放大的价格在右、统一固定位置**；不同套餐名称长度不应改变价格定位。
- 「推荐」标签在**卡片内右上角**，不会挤压或移动价格、名称；是否推荐的业务规则**尚未确认**，不得自行启用算法。
- 周期套餐：仅显示后台确实配置价格的周期选项；切换周期后同步更换实际价格。
- 一次性套餐：**仅一个购买操作按钮**，不出现第二个伪按钮或周期胶囊。
- 如后台提供，显示套餐真实名称、简介、流量、设备数量及完整权益；不编造「基础版」「轻量订阅」等等级或营销词。
- 删除冗余「套餐说明」入口及面向开发者的提示。禁止因为 HTML 演示数据缺省而擅自省略一次性套餐的权益。
- 保持暖白／浅珊瑚卡片及已确定的间距、圆角、选中态。

## 工程边界与验收流程

1. **此提交只归档 HTML 模板，不修改任何 Flutter 页面、支付流程、后端接口或导航代码。**
2. 后续实施必须由用户明确指示开始，不能因为模板已上传就自动开发或合并。
3. 工程师应以本目录两个 HTML 为**界面呈现基准**，以后台真实数据为**业务信息基准**，不要自行创造设计或业务字段。
4. 如实现受 Flutter／设备约束，需要偏离模板，应先列明差异并取得用户确认，不能先改后通知。
5. 修改后对比 HTML 与 Android 实际截图（浅色和深色、窄屏和常规屏），核对筛选、周期、价格、购买入口、返回与底部导航，再交付用户验收。
6. **任何新的视觉优化都属于新提案，而不是默认授权改动。** 未经确认不得替换已验收结构。

其它页面、桌面端及现有功能不受这两份模板自动约束或更改。
